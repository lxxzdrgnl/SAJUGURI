# 사주구리 디자인 시스템 개편 + 진열대 홈 — 설계

> 2026-10-21 브레인스토밍으로 확정. 3단계 개편 중 **1번**.
> 2번 "구리구리 상담"(상담 탭 대체), 3번 "테마 상품 틀"은 별도 설계 문서로 진행한다.
> 시안: 진열대 홈 L/D — https://claude.ai/artifact/2F1xkybvWFbqdrZYGJw5o2 (구성 참고용, 픽셀 기준 아님)

## 1. 왜 바꾸나

- 지금 메인은 같은 무게의 브루탈 카드가 메뉴판처럼 늘어서 있다. 처음 온 사람은
  뭘 눌러야 할지 모르고, Y2K 크롬 배너와 브루탈 카드가 따로 논다. 사용자가 꼽은
  "제일 문제인 화면"이 메인이다.
- 사주구리를 단순 사주 사이트에서 **상품 진열대가 있는 사주 서비스**로 바꾼다.
  레퍼런스는 월명관(wolmyung.com, 밝은 일러스트 진열대)과 용용사주(yongyong.ai,
  어두운 포스터 진열대). **구조만 참고하고 이름·문구·그림·색은 사주구리 것으로 새로
  만든다** (베끼기 금지).
- 상품 우선순위(사용자 확정): **① 오늘의 운세(가장 주력) ② 구리구리 상담 ③ 테마 상품들.**

## 2. 목표 / 비목표 / 실패 조건

**목표**
- "비비드 캔디 브루탈" → 새 디자인 시스템(라이트 + 다크). `docs/design.md` 재작성.
- 홈을 진열대로 재구성. 하단 탭 바 제거, 우측 상단 ≡ 드로어.
- **전 화면**에 새 시스템 적용 (사용자 확정). 단 **오늘의 운세 스토리 화면은 그대로**.
- 상품 일러스트를 AI로 생성하는 스크립트 + 홈에 보이는 상품 전부의 일러스트.
- 상품 열람 기록 **수집 시작** ("많이 본" 선반·랭킹을 나중에 실제 통계로 바꾸기 위한 데이터 축적).
- **화면별로 나눠 배포** (사용자 확정) — §9 순서.

**비목표 (이번에 안 함)**
- 구리구리 상담 자체(대화 방식·진행도·보고서·심리 이론 RAG·밤의 상담실 UI) → 2번.
- 테마 상품 전용 리포트 생성 → 3번. 이번엔 카드만 "곧 나와요".
- `apps/mobile`(Expo) 반영 → 웹 확정 후. 단 토큰은 `packages/design`에 둬서 재사용 가능하게.
- 리뷰/후기 섹션 (실제 후기가 없음 — 가짜 후기 금지). 결제/유료 구간 (전부 무료).
- 공지사항·고객센터 (없음).

**실패 조건 (기술적으로 돌아가도 실패)**
- 만세력 분석·리포트·궁합의 **기능이 하나라도 빠짐** (AGENTS.md G3 — 재배치이지 축소 아님).
- 오늘의 운세 스토리 화면의 룩·동작이 바뀜.
- 다크/라이트 중 한쪽에서 글자가 안 읽히는 화면이 있음.
- 실제가 아닌 수치(가짜 조회수·가짜 후기·기관 로고)를 사실처럼 보여줌.
- 가로 스크롤, PC 전용 레이아웃.

## 3. 디자인 시스템 (새 design.md의 뼈대)

### 3.1 방향
- 레퍼런스 결: **넓은 여백 + 얇은 라인 + 둥글고 큰 카드**. 개성은 화면 장식이 아니라
  **너구리 스티커 일러스트**와 **굵은 손글씨풍 제목 글꼴**이 담당한다.
- 브루탈(굵은 잉크 테두리 + 오프셋 그림자)은 **완전히 걷어낸다** (사용자 확정).
  `BrutalCard`, `shadow-brutal*` 등 브루탈 유틸리티는 새 카드/버튼 컴포넌트로 교체하고 제거한다.
- 포인트 컬러는 **옐로(#FFD900) 유지** (사용자 확정) — 로고 "구리" 하이라이트, 주요 버튼,
  활성 탭 표시. 너구리 스티커가 노랑이라 브랜드가 이어진다.

### 3.2 모드
- 라이트 / 다크 / 시스템. **기본 = 시스템 따라가기** (사용자 확정). 선택은 드로어에서, 쿠키/로컬에 저장
  (SSR 깜빡임 없게 — 구현은 빌더 재량).
- 같은 구성, 색만 다름. 라이트 = 흰 바탕 + 크림·파스텔 카드. 다크 = 검정에 가까운 바탕 +
  깊은 색의 포스터 카드 (시안 L/D 참고).
- 예외: **오늘의 운세 스토리**는 모드와 무관하게 지금 비비드 룩 유지.
  **구리구리 상담실(2번)**은 두 모드 모두 "밤의 상담실"(딥 틸 밤하늘) — 2번에서 정의.
- 토큰은 의미 기반 이름(배경, 표면, 라인, 본문, 보조 텍스트, 포인트, 위험 등)으로 정의하고
  라이트·다크 값을 각각 둔다. 웹은 CSS 변수, 공유 값은 `packages/design/src/tokens.ts`.
- `apps/mobile`이 지금 `packages/design`의 기존 토큰(`bgBase`, `shadow.brutal` 등)을 읽고 있다.
  **새 의미 토큰은 기존 export 옆에 추가하고 기존 것은 지우지 않는다** — 모바일은 그대로 돌아가야 하고,
  `packages/design` 테스트와 모바일 typecheck는 계속 통과해야 한다 (내 판단). 기존 토큰 정리는 모바일 이관 때.
- 오행 5색·기둥 틴트·차트 색은 **두 모드에서 대비를 다시 맞춘 값**을 정의한다
  (다크 배경에서 금(#7D7A70)·토 등이 죽지 않게).

### 3.3 글꼴
- 제목·상품명·히어로: **굵은 손글씨풍 한글 디스플레이 글꼴** (사용자 확정). 후보는 OFL 등
  상업 사용 가능한 무료 글꼴 중 빌더가 2~3개 시안으로 비교해 사용자에게 고르게 한다.
- 본문: Pretendard 유지. 간지 한자/한글: Noto Serif KR 유지 (기존 규칙).

### 3.4 아이콘·이모지
- UI 이모지 금지(G2) 유지. 레퍼런스의 섹션 이모지(💌🔥) 자리는 스트로크 SVG 아이콘 또는 없음.
- 그라데이션 규칙 갱신: 다크 포스터 카드의 은은한 방사형 배경은 허용한다 (G2 "그라데이션은 운세
  스토리 전용"을 design.md와 AGENTS.md에서 이 예외까지 포함하도록 수정).

## 4. 네비게이션

- **하단 탭 바 제거** (`components/TabBar.tsx`, `[locale]/layout.tsx`의 렌더). 데스크탑 상단 탭도 제거.
- **헤더 (홈)**: 로고 · 일간 칩 · 검색 · ≡.
  - 일간 칩: `壬水 용재 · 임수 일간` 형식(대표 만세력). **누르면 내 만세력 분석 화면으로 이동** (사용자 확정).
  - 비로그인 또는 만세력 없음: 칩 자리에 **"내 일간 찾기"** 버튼 → 생년월일 입력 → 만세력 생성.
- **하위 화면 헤더**: ← 뒤로 + 제목 + ≡ (빌더 재량으로 통일).
- **≡ 드로어** (오른쪽에서 밀려 나옴, 뒤 화면 딤, 바깥 탭으로 닫힘):
  1. 프로필·로그인 영역 (로그인 전 "로그인") → 마이
  2. 내 만세력 목록 (기존 `/manse` 목록 기능 이관 — 추가·대표 지정·삭제)
  3. 보관함: 지난 상담 · 리포트 · 궁합 · 운세 기록, 공유 관리
  4. 화면 모드(라이트/다크/시스템) · 언어(ko/en)
  5. 로그아웃
  - 홈에 있는 상품 입구는 드로어에 **중복하지 않는다** (사용자 확정).
- 기존 `/my` 페이지의 기능(리포트 목록·운세 기록·공유 관리·설정)은 드로어/보관함으로 흡수하거나
  유지하되, 빠지는 기능이 없어야 한다. 배치는 빌더 재량.

## 5. 홈 (위에서 아래로)

1. **헤더** (§4)
2. **카테고리 탭**: 전체 · 운세 · 연애 · 재회 · 궁합 · 직업 · 재물 (안은 시안 기준, 최종 목록은 빌더가
   상품 데이터에서 도출). **전체 = 아래 큐레이션 홈, 나머지 탭 = 그 카테고리 상품만 포스터 그리드로 필터** (사용자 확정).
3. **히어로 캐러셀**: 첫 장은 **항상 오늘의 운세**, 뒤에 추천 2~3장(구리구리 상담, 시즌 상품 등).
   - 오늘의 운세 카드 — 안 본 날: "매일 무료" 리본, "아직 안 봤어", 너구리 일러스트 + 말풍선, [오늘 하루 넘겨 보기].
   - **본 날: 점수 + 한 줄 요약 카드로 바뀜** + 다시 보기 + "이 얘기 구리구리랑 더 해 볼래?" (사용자 확정).
   - 비로그인: 누르면 **생년월일 입력 → 바로 운세** (로그인 없이 체험). 저장할 때만 로그인 유도 (사용자 확정).
     게스트 운세는 이미 지원된다 (`POST /api/daily/story` 게스트 허용, localStorage로 하루 1회 캐시).
4. **구리구리 상담실 카드**: 2번 전까지는 **기존 AI 상담(`/chat`)으로 연결**, 새 토큰만 입힌 상태 (사용자 확정).
5. **지금 내 상황은?** 2×2: 썸 타는 중 · 헤어졌어요 · 회사 그만둘까 · 돈이 안 모여요 (문구 시안 기준).
   각 칸은 **해당 테마 상품(곧 나와요)으로** 연결 (사용자 확정).
6. **맞춤 선반**: "임수 일간이 많이 본 사주"(일간 기준) 등. **처음엔 큐레이션 목록**(일간·나이대별로 미리 정한
   추천), 이용 기록이 쌓이면 실제 통계로 전환 (사용자 확정). 비로그인은 "요즘 많이 보는"으로 대체.
   큐레이션인 동안 "많이 본"이라는 문구가 사실과 다르지 않게, 문구는 "임수 일간에게 추천" 류로 쓰고
   통계 전환 후에만 "많이 본"을 쓴다 (내 판단 — 실패 조건 "가짜 수치" 회피).
7. **랭킹 리스트** — 큐레이션 동안은 제목을 "구리구리 추천"으로, 통계 전환 후 "지금 제일 많이 보는"으로
   바꾼다 (내 판단). 1~3(또는 5)위.

### 5.0 이용 기록 수집 (사용자 확정 — 이번에 수집만 시작)
- 상품 카드를 열거나 상품 화면에 진입할 때 열람 이벤트를 백엔드에 기록한다: 상품 id, 시각, 로그인 사용자면
  user_id, 그리고 집계용으로 대표 만세력의 일간·나이대·성별(있을 때). 게스트는 익명으로.
- 새 테이블 + alembic 마이그레이션 + 기록용 엔드포인트. 실패해도 화면 동작에 영향 없게(fire-and-forget).
- 집계 API와 화면의 통계 전환은 **이번 범위 밖**. 전환 기준(최소 표본 수 등)은 데이터가 쌓인 뒤 정한다.

### 5.1 상품 목록 (1번 시점)
| 상품 | 상태 | 연결 |
|---|---|---|
| 오늘의 운세 | 있음 | 운세 스토리 |
| 구리구리 상담 | 있음(기존 상담) | `/chat` → 2번에서 교체 |
| AI 사주 리포트(10탭) | 있음 | `/report/new` |
| 궁합 리포트 | 있음 | `/compatibility/new` |
| 한 번 물어보기 | 있음 | `/question` |
| 썸 상대 마음 · 재회 흐름 · 퇴사·이직 타이밍 · 올해 돈 흐름 | **곧 나와요** | 안내 시트 |

- **"곧 나와요" 탭** → 안내 시트: "준비 중이에요. 지금은 이 고민 구리구리한테 먼저 얘기해 볼래?" +
  [구리구리 상담하기](그 주제를 첫 메시지 힌트로 넘김 — 넘기는 방식은 빌더 재량) (사용자 확정).
- 상품은 **데이터로 정의**한다(id, 이름, 한 줄 설명, 카테고리, 일러스트, 상태 available/coming_soon, 링크).
  3번에서 이 정의가 리포트 생성 스펙까지 확장된다. 위치는 `packages/core` 또는 `packages/api-client`
  (G1 순수성 준수) — 빌더 재량. ko/en 문구 포함.
- **검색** (사용자 확정 — 넣기): 상품 + 고민 키워드로 찾는다. 상품마다 키워드 목록을 둔다
  ("재회" → 재회 흐름, "이직" → 퇴사·이직 타이밍). 맞는 게 없으면 "구리구리한테 이 고민 상담하기"로 연결.
  보관함 기록 검색은 안 함.

## 6. 일러스트 (AI 생성)

- 스타일: **지금 너구리 스티커처럼 굵은 외곽선의 귀여운 캐릭터, 배경 없음(투명)** (사용자 확정).
  배경은 카드 색이 채운다 → 같은 그림을 라이트·다크 공용.
- 도구: OpenAI 이미지 생성(gpt-image-1, 편집/참조 입력) — 기존 OpenAI 통일 정책. 기존 스티커
  (`apps/web/public/mascot/*.png`, `mascot.svg`)를 참조 이미지로 넣어 **캐릭터 일관성** 유지.
- 저장소에 생성 스크립트를 둔다: 상품 정의의 그림 설명(장면 프롬프트) → PNG(투명) → `apps/web/public/products/`.
  API 키는 환경변수, 결과물만 커밋.
- 범위: **홈에 보이는 상품 전부** + 빈 상태·로그인 안내 등 약 12장 (사용자 확정).
- **검수 필수**: 생성 결과는 사용자가 확인한 뒤 반영한다.
- 실행: 클로드가 백엔드와 같은 OpenAI 키로 돌린다. **총 예산 $10 이내**(재생성 포함), 실행 전 예상 비용을 알린다 (사용자 확정).
- 개발 중에는 기존 스티커(`public/mascot/*.png`)와 Pretendard 굵게를 임시로 쓰고, 그림·글꼴은 검수가 끝나는
  대로 교체한다 — 검수를 기다리느라 구현을 멈추지 않는다 (내 판단).

## 7. 다른 화면에 새 시스템 적용

## 8. 레이아웃·i18n·기타 제약

- 모바일 단일 컬럼 max-width 640px 가운데 정렬, PC 전용 레이아웃 없음 (사용자 확정, G2).
- 새 UI 문자열은 전부 next-intl ko+en 동시 작성 (G7). 상품 이름·설명·키워드도 ko/en.
- `packages/` 순수성(G1): 상품 정의·검색 매칭 로직은 플랫폼 무관 TS.
- `frontend/`(Nuxt 레거시)는 건드리지 않는다.
- 문서 갱신: `docs/design.md` 전면 재작성, AGENTS.md G2(그라데이션·브루탈 규칙) 갱신.
  AGENTS.md G8(채팅 반말) 변경은 2번에서.

## 9. 배포 순서 (화면별 — 사용자 확정)

각 단계는 `dev` → `main`으로 나가서 사용자에게 보인다. 한동안 옛 화면과 새 화면이 섞이는 걸 전제로 한다.
1. **토대 + 홈 + 네비**: 새 토큰·새 카드/버튼 컴포넌트·글꼴, 진열대 홈, ≡ 드로어, 하단 탭 제거, 상품 정의,
   검색, "곧 나와요" 시트, 이용 기록 수집. 탭 바 제거와 드로어는 같은 배포여야 한다(진입로가 끊기지 않게).
   드로어가 만세력 목록·보관함·마이로 가는 길을 전부 대신해야 한다.
2. 이후 화면별 교체: 만세력 입력·분석 → 리포트 → 궁합 → 한 번 물어보기 → 기존 상담(토큰만) → 마이/보관함 → 공유 페이지·OG.
   순서는 빌더가 의존성을 보고 조정 가능.
3. **다크 모드는 마지막에 켠다** (내 판단): 모든 화면이 새 토큰으로 바뀌기 전에는 화면 모드 선택을 노출하지 않고
   라이트로 고정한다. 그래야 옛 화면만 다크에서 깨지는 일이 없다. 토큰은 처음부터 라이트·다크 값을 다 정의해 둔다.
4. **브루탈 유틸리티(`BrutalCard`, `shadow-brutal*`) 제거는 마지막 화면이 바뀐 뒤** — 그 전엔 남아 있는 화면용으로 공존.
5. 일러스트·글꼴 교체는 검수 끝나는 대로 아무 단계에나 끼워 넣는다.
